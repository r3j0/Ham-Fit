# 최신 백엔드 프론트 연동

기준: `origin/feat/backend/personalized-recommendation`, `a29fa291297ba9c841199cbfa362b1265d4bd614` (2026-09-29).
현재 main의 프론트 화면·인증·계정별 저장 복구 구조를 유지한다. 백엔드와 data-analysis는 변경하지 않는다.

## 보유 운동 도구

`/account/preferences`에 10종 복수 선택과 없음(빈 배열)을 제공한다. 기존 운동량·목적과 함께 `GET/PATCH /users/me/preferences`에 연결하고, 변경한 필드만 전송한다. 저장 결과가 불명확하면 원래 PATCH를 유지하고 재시도하며, 계정·화면 변경 후 늦은 응답은 폐기한다. 설정 변경은 다음 신규 루틴 생성부터 적용된다.

백엔드 브랜치의 도구 UI·어댑터·검사를 기존 프론트에 적용했다. API에 ownedTools가 없으면 조회 오류를 표시하므로 DB 마이그레이션과 최신 API 배포가 먼저다.

검증: 린트·타입·단위 126개·프로덕션 빌드 통과. Chromium 관련 11개 통과(실제 최신 API 2개, 오류·복구·반응형 계약 9개). 실제 PostgreSQL은 이번 검증의 별도 임시 디렉터리/포트에만 생성했다. 새로고침·재로그인·별도 브라우저 복원, 전체 선택/해제, 사용자 격리와 기존 계정 정보 보존을 확인했다.

## 검증 환경

기존 개발 서버와 캐시 충돌을 피하기 위해 `NEXT_BUILD_DIR=.next-integration`을 지원한다. 기본 실행 경로는 기존 `.next`다. 검증 서버는 `NEXT_PUBLIC_API_BASE_URL=http://localhost:3101/api/v1`로 빌드하고 3100 포트에서 실행했다. 테스트의 `E2E_BASE_URL`과 `E2E_API_BASE_URL`은 각각 이 프론트와 API 주소를 사용한다. 실제 배포 환경과 DB는 변경하지 않았다.

## 여러 운동으로 구성된 루틴

`/workout-routines/current`, `/next`, `/history`, `/:id`, `/:id/items/:itemId/events`를 연결했다. 오늘의 모든 처방·순서·세트·휴식·완료 수를 표시하고 기존 재생 세션, 이벤트 큐, 재접속 복구, 달력과 다시보기를 재사용한다. `/next`는 한국 시간 **내일** 운동을 만들며 자동 생성하지 않는다. 응답 유실 후 새로고침해도 동일 요청 키를 재사용한다. 미래 운동은 상세 처방만 표시하며 재생을 시작하지 않는다.

기존 단일 운동 기록도 유지하고, 최신 백엔드의 `RECOMMENDATION_NOT_CONNECTED`는 이전 기록 조회 제한으로 명시한다. 운동 이력의 두 API 커서는 별도로 보관하여 더 보기 실패 시 이미 읽은 기록을 보존한다. 생년월일·측정·목적 준비 조건에는 해당 설정 화면 링크를 제공한다.

검증: 단위 129개 통과. 실제 Python 엔진의 루틴 생성·저장 복원·동일 날짜 재사용(201/200)·예약일 전 이벤트 거절을 검증했다. 브라우저 계약 검사에서 개별 운동 완료·완료 영상 재시청·응답 유실 복구·페이지 실패 복구를 확인했다. 기존 플레이어의 인증·복구·측정 타이머 구조는 유지한다. 외부 영상 제공 여부는 서버의 검증된 미디어 상태를 따른다.

## 그룹

메인과 내 프로필에서 `/groups`로 진입한다. 내 그룹 전체 조회, 이름·소개·정원을 통한 생성, 초대 코드 보기/복사, 가입 신청, 그룹장 승인·거절과 상태별 신청 목록, 멤버 프로필, 정보 수정, 강퇴·위임·탈퇴·삭제를 지원한다. 생성·가입 신청은 계정별 요청 저장소로 응답 유실 후 동일 키와 본문을 복원한다. 읽기 페이지의 잘못된 응답을 빈 목록으로 바꾸지 않으며, 화면 복귀 시 권한과 멤버 상태를 다시 읽는다. 그룹장 계정 탈퇴 409는 이메일 충돌로 표시하지 않고 그룹 관리로 안내한다.

검증: 실제 API 두 계정으로 생성 → 수정 → 초대 → 거절 → 재신청 → 승인 → 멤버 조회 → 무권한 수정 거절 → 그룹장 계정 탈퇴 차단 → 강퇴 → 재가입 → 위임 → 탈퇴 → 삭제 전 과정을 통과했다. 응답 유실·새로고침 복원, 다른 기기의 권한 변경, 잘못된 응답 거절을 별도 Chromium 계약 검사로 확인했다. 320/390/1280px 가로 넘침 검사와 화면 검토를 수행했다.

## 알림

메인 및 내 프로필에서 `/account/notifications`로 진입한다. 가입 신청 도착·승인·거절을 구분하고, 서버에 읽음 상태를 저장하며 관련 그룹으로 연결한다. 전체 페이지를 중복 없이 병합하고 최신 생성 순으로 표시한다. 화면 복귀/명시적 새로고침/화면이 보이는 동안 60초 간격으로 최신 상태를 확인한다. 서버에 없는 푸시 발송이나 초대 코드 자동 회전 기능은 추가하지 않는다.

검증: 실제 두 계정의 신청·거절·승인 알림, 읽음 후 새로고침 복원, 타인 알림 읽기 404를 확인했다. 페이지 병합, 읽음 실패 후 재시도, 잘못된 응답, 320px 표시도 검증했다.

## 활동 통계

홈과 프로필은 `GET /users/me/profile/activity`의 실제 `streak`를 사용한다. 그룹원 상세도 같은 서버 집계 값을 표시한다. 프로필의 기존 고정 예시 숫자를 제거하고 API가 제공하지 않는 최장 스트릭·레벨·컬렉션·총 운동일은 집계 준비 중으로 표시한다. 가입 경과일은 기존 실제 가입일 계산을 유지한다. 조회 실패·다른 사용자 응답은 0이나 이전 성공값으로 표시하지 않는다.

**백엔드 제한:** 현재 streak 집계는 기존 `UserCurriculumAssignment` 완료만 포함하며 새 `workout_routines` 완료는 포함하지 않는다. 화면에 이 범위를 명시한다. 달력/최근 완료 표시에는 새 루틴의 실제 완료 날짜가 반영된다. 서버 수정 없이 두 의미를 동일하다고 표시하지 않는다.

검증: 서버 값과 화면 복귀 갱신, 조회 실패/재시도, 응답 사용자 검증을 확인했다. 프로필 외형·활동·그룹·알림·달력 관련 Chromium 21개 통과, 320/390/430/1280px 기존 배치와 계정 메뉴를 검증했다.

## 실제 재생 통합 검사

`tests/e2e/workouts.spec.ts`도 최신 루틴 API로 전환했다. 사용자와 실제 추천 결과를 생성하고 전용 임시 DB에 오늘 배정을 복사하는 **테스트 전용 fixture**를 사용한다. `/next`의 내일 생성 정책이나 DB 불변성 트리거를 변경하지 않는다. 영상 전송/검증 메타데이터만 12초 MP4 fixture로 대체하며 실제 원본 영상의 외부 서비스 가용성을 이 검사로 보증하지 않는다. 시작·시청 구간·종료·재개·완료·재시도 키·다른 기기 충돌·DB 복원은 실제 API로 검증한다.

전체 재생 검사에는 `E2E_ALLOW_TEST_SEED=1` 및 `E2E_BACKEND_ROOT=/private/tmp/<격리된 백엔드>/backend`를 명시해야 한다. fixture는 임시 경로의 development/loopback DB와 해당 검사 계정만 허용한다. 테스트 계정은 종료 시 삭제한다. 일반 앱 실행에서는 이 fixture를 불러오지 않는다.

추가 회귀 검토에서 실제 UUID 정렬로 처방 순서가 바뀔 수 있는 부분을 수정했다. 같은 루틴 안에서는 서버 `order`를 우선하며, UUID가 역순인 단위 검사로 이를 고정했다.
