# 최신 백엔드 프론트 연동

기준: 백엔드 PR #9, `62b3f146a6c0a18be2eabded363685a23791edb8` (2026-09-30). 프론트엔드 `68c2b1e`에서 이어서 호환 작업을 적용했다.
기존 프론트 화면·인증·계정별 저장 복구 구조를 유지한다. 백엔드와 data-analysis는 변경하지 않는다.

## 보유 운동 도구

`/account/preferences`에 6종(밴드·덤벨/아령·짐볼·줄넘기·스텝박스·볼) 복수 선택과 없음(빈 배열)을 제공한다. 기존 운동량·목적과 함께 `GET/PATCH /users/me/preferences`에 연결하고, 변경한 필드만 전송한다. 저장 결과가 불명확하면 원래 PATCH를 유지하고 재시도하며, 계정·화면 변경 후 늦은 응답은 폐기한다. 설정 변경은 다음 신규 루틴 생성부터 적용된다.

백엔드 브랜치의 도구 UI·어댑터·검사를 기존 프론트에 적용했다. API에 ownedTools가 없으면 조회 오류를 표시하므로 DB 마이그레이션과 최신 API 배포가 먼저다.

검증: 린트·타입·단위 126개·프로덕션 빌드 통과. Chromium 관련 11개 통과(실제 최신 API 2개, 오류·복구·반응형 계약 9개). 실제 PostgreSQL은 이번 검증의 별도 임시 디렉터리/포트에만 생성했다. 새로고침·재로그인·별도 브라우저 복원, 전체 선택/해제, 사용자 격리와 기존 계정 정보 보존을 확인했다.

## 검증 환경

기존 개발 서버와 캐시 충돌을 피하기 위해 `NEXT_BUILD_DIR=.next-integration`을 지원한다. 기본 실행 경로는 기존 `.next`다. 검증 서버는 `NEXT_PUBLIC_API_BASE_URL=http://localhost:3101/api/v1`로 빌드하고 3100 포트에서 실행했다. 테스트의 `E2E_BASE_URL`과 `E2E_API_BASE_URL`은 각각 이 프론트와 API 주소를 사용한다. 실제 배포 환경과 DB는 변경하지 않았다.

## 여러 운동으로 구성된 루틴

루틴 요청만 `/api/v2/workout-routines`의 `/current`, `/today`, `/history`, `/:id`, `/:id/items/:itemId/events`로 보낸다. 인증·측정·계정·그룹·기존 단일 운동은 v1을 유지한다. `/today`는 한국 시간 오늘의 루틴을 하루 한 번 생성하며 자동 생성하지 않는다. 응답 유실 후 새로고침에서도 동일 요청 키를 재사용하고, 이전 `routine:next`의 미확정 요청도 원래 키로 확인한다. 미래/과거 배정의 날짜와 처방을 오늘로 바꾸지 않는다.

오늘의 모든 처방·순서·세트·휴식·완료 수를 표시한다. nullable `cardioRecommendation`은 영상 목록 뒤에 걷기/뛰기와 분을 안내하며 가짜 영상·타이머·완료 이벤트를 생성하지 않는다. null 또는 필드가 누락된 이전 응답은 안내를 생략한다. `estimatedMinutes`는 `영상 운동 예상 …분 (유산소 제외)`로 구분한다. 항목별 실제 시청 구간이 80% 이상일 때 서버가 완료로 판정하고, 전체 영상 완료 여부도 서버 값을 따른다. `pause` 이후 미완료 항목은 `start`로 재개한다. 완료/종료 확인창을 여는 pause가 먼저 중단 상태를 확정하지 않도록 미디어 이벤트를 처리한다.

응답의 `serverTime`, `recordingAllowed`, `recordingExpiresAt`을 검증하고 요청 왕복 지연을 제외한 `performance.now()` 마감 시각을 사용한다. 시스템 날짜 변경·백그라운드 타이머 지연과 무관하게 공통 record 진입과 전송 직전에 검사한다. 자정이 지나거나 409 `ROUTINE_EXPIRED`를 받으면 큐·재시도를 종료하고 미확정 상태는 GET으로 확인한다. 같은 항목 revision에서도 서버 날짜 정보는 갱신한다. 재생 중인 영상 요소·재생 위치를 초기화하거나 멈추지 않는다. 과거 루틴은 다섯 상태 모두 기록 없는 영상 시청을 제공하고 과거 시청을 같은 영상의 오늘 항목에 저장하지 않는다.

기존 단일 운동 기록도 유지하고, 최신 백엔드의 `RECOMMENDATION_NOT_CONNECTED`는 이전 기록 조회 제한으로 명시한다. 운동 이력의 두 API 커서는 별도로 보관하여 더 보기 실패 시 이미 읽은 기록을 보존한다. 생년월일·측정·목적 준비 조건에는 해당 설정 화면 링크를 제공한다.

검증: 단위 129개 통과. 실제 Python 엔진의 루틴 생성·저장 복원·동일 날짜 재사용(201/200)·예약일 전 이벤트 거절을 검증했다. 브라우저 계약 검사에서 개별 운동 완료·완료 영상 재시청·응답 유실 복구·페이지 실패 복구를 확인했다. 기존 플레이어의 인증·복구·측정 타이머 구조는 유지한다. 외부 영상 제공 여부는 서버의 검증된 미디어 상태를 따른다.

## 그룹

하단 메뉴의 내 그룹 아이콘에서 `/groups`로 진입한다. 내 그룹 전체 조회, 이름·소개·정원을 통한 생성, 초대 코드 보기/복사, 가입 신청, 그룹장 승인·거절과 상태별 신청 목록, 멤버 프로필, 정보 수정, 강퇴·위임·탈퇴·삭제를 지원한다. 생성·가입 신청은 계정별 요청 저장소로 응답 유실 후 동일 키와 본문을 복원한다. 읽기 페이지의 잘못된 응답을 빈 목록으로 바꾸지 않으며, 화면 복귀 시 권한과 멤버 상태를 다시 읽는다. 그룹장 계정 탈퇴 409는 이메일 충돌로 표시하지 않고 그룹 관리로 안내한다. 생성과 초대 가입 폼은 두 열로 배치하고, 관리 버튼과 신청 상태 선택도 두 칸씩 배치한다.

검증: 실제 API 두 계정으로 생성 → 수정 → 초대 → 거절 → 재신청 → 승인 → 멤버 조회 → 무권한 수정 거절 → 그룹장 계정 탈퇴 차단 → 강퇴 → 재가입 → 위임 → 탈퇴 → 삭제 전 과정을 통과했다. 응답 유실·새로고침 복원, 다른 기기의 권한 변경, 잘못된 응답 거절을 별도 Chromium 계약 검사로 확인했다. 320/390/1280px 가로 넘침 검사와 화면 검토를 수행했다.

그룹 정보 수정은 편집 시작 시점과 비교하여 변경한 필드만 PATCH한다. 소개를 편집하는 동안 다른 기기가 바꾼 이름을 보존하는 실제 동시 수정 시나리오도 검증했다. 권한을 잃으면 그룹원 관리 대화상자와 설정의 편집·삭제 기능을 숨긴다. 일반 그룹원도 설정에서 탈퇴할 수 있다.

## 알림

메인 우측 상단 종 아이콘에서 `/account/notifications`로 진입한다. 가입 신청 도착·승인·거절을 구분하고, 서버에 읽음 상태를 저장하며 관련 그룹으로 연결한다. 전체 페이지를 중복 없이 병합하고 최신 생성 순으로 표시한다. 카드 여백과 글자 크기를 줄이고 링크와 읽음 버튼을 두 열로 배치한다. 읽음 저장에 성공하면 즉시 목록에서 제거하며, 새로고침 이후에도 서버의 읽음 상태를 기준으로 제외한다. 읽음 저장 실패 시에는 알림을 유지한다. 서버에는 기존 읽음 API를 사용하며 알림 데이터를 영구 삭제하는 API는 없다. 화면 복귀/명시적 새로고침/화면이 보이는 동안 60초 간격으로 최신 상태를 확인한다. 서버에 없는 푸시 발송이나 초대 코드 자동 회전 기능은 추가하지 않는다.

검증: 실제 두 계정의 신청·거절·승인 알림, 읽음 상태 저장, 타인 알림 읽기 404를 확인했다. 페이지 병합, 읽음 실패 후 재시도, 잘못된 응답, 320px 표시도 검증했다.

## 활동 통계

홈과 프로필은 `GET /api/v1/users/me/profile/activity`의 실제 `streak`를 사용한다. 프로필과 그룹원 상세는 서버가 제공하는 `longestStreak`, `totalWorkoutDays`도 표시한다. 서버는 모든 영상 항목을 완료한 루틴과 기존 완료 이력을 날짜별로 합쳐 집계한다. 레벨·컬렉션과 그룹원의 오늘 완료 여부는 아직 응답에 없으므로 실제 값으로 꾸미지 않는다. 조회 실패·다른 사용자 응답은 0이나 이전 성공값으로 표시하지 않는다.

`profileCharacter`의 저장 코디를 검증해 홈 그룹 슬라이드·그룹원 행·그룹원 상세에 반영한다. 기존 출력기를 재사용하며 현재 서버 카탈로그의 cream/gray × 13자세와 빈 의상 조합만 수용한다. 과거 응답의 null은 기본 크림으로 표시한다. 알 수 없는 ID·자세·의상·불일치 렌더링은 응답 오류로 처리한다. 그룹 슬라이드의 본인 제외·닉네임·그룹명·전환과 기존 반응형 구조를 유지한다. 상점 구매·코디 편집 화면은 이번 호환 변경 범위에 포함하지 않는다.

검증: 서버 값과 화면 복귀 갱신, 조회 실패/재시도, 응답 사용자 검증을 확인했다. 프로필 외형·활동·그룹·알림·달력 관련 Chromium 21개 통과, 320/390/430/1280px 기존 배치와 계정 메뉴를 검증했다.

## 실제 재생 통합 검사

`tests/e2e/workouts.spec.ts`는 실제 v2 `/today`로 추천을 생성하며 DB에 오늘 배정을 복사하는 fixture가 더 이상 필요하지 않다. 영상 전달/검증 메타데이터만 12초 MP4로 대체한다. 실제 시청 구간·탐색 제외·80% 미만 완료 요청·중단 후 start·복구 키와 저장 상태를 실제 API로 확인한다. 80% 경계와 다른 기기의 완료는 명시적인 이벤트 구간을 보내 API 계약을 검사하며, 이를 실제 외부 영상 시청 성공이라고 표시하지 않는다. 테스트 계정은 종료 시 삭제한다. 운영 데이터는 변경하지 않는다.

추가 회귀 검토에서 실제 UUID 정렬로 처방 순서가 바뀔 수 있는 부분을 수정했다. 같은 루틴 안에서는 서버 `order`를 우선하며, UUID가 역순인 단위 검사로 이를 고정했다.

공용 테스트 IP의 서버 요청 제한은 유지한다. 계정 생성·정리 중 명시적인 429가 오면 `live-api-fixtures.ts`에서 서버가 지정한 대기 후 재시도한다. 응답 유실이나 다른 실패를 이 준비 로직에서 자동 재전송하지 않는다. 기존 파일의 CRLF/LF를 보존하도록 Prettier `endOfLine: auto`를 명시했다.

## 브라우저 피드백 반영

홈의 그룹·알림 본문 링크와 프로필의 해당 메뉴를 제거했다. 알림은 메인 우측 상단 종 아이콘으로, 그룹은 하단의 독립 아이콘으로 이동했다. 하단 메뉴는 운동·메인·내 그룹·내 프로필 순서이며 그룹 하위 화면에서도 내 그룹을 활성 표시한다. 홈·프로필의 지정된 연속 운동 안내 문구를 삭제했다.

알림은 작은 카드와 두 열의 버튼을 사용한다. 읽음 상태를 서버에 저장한 뒤 목록에서 즉시 제거하고, 이미 읽은 알림은 전체 페이지를 불러온 후에도 제외한다. 읽음 저장 실패 시 알림을 유지하고 재시도할 수 있다. 그룹 생성·초대 가입 폼과 그룹 관리 선택 버튼은 두 열을 유지한다.

검증: 린트·타입·포맷·프로덕션 빌드, 단위 130개, 관련 Chromium 통합·회귀 27개 통과. 320/390/702/1280px에서 알림 카드 높이 160px 이하, 버튼 두 열과 44px 이상 터치 영역, 그룹 폼 두 열, 가로 넘침 없음, 메뉴 활성 상태·키보드 이동·이전 화면 복귀를 확인했다. 960–1440px 기존 화면 회귀와 실제 두 계정의 그룹 관리·알림 읽음 저장·새로고침 후 숨김도 통과했다.

### 그룹 화면 추가 피드백 (2026-09-29)
