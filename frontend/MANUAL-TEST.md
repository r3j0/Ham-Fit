# 캐릭터·상점·운동·그룹 수동 테스트

2026-10-01 준비한 **이 컴퓨터 전용** 테스트 환경입니다. 프론트는 현재 `feat/frontend/avatar-shop` 작업 내용, API는 검증한 BE PR #9의 `f5774815fa7a42386672683fbf227a6e937ed0eb`를 사용합니다. 운영 계정이나 기존 개발 DB와 분리했습니다.

## 접속과 계정

- 브라우저: <http://localhost:3020/login>
- API: <http://localhost:3021/api/v1>, 운동 루틴만 `/api/v2`.
- 전용 PostgreSQL: `127.0.0.1:17501`.
- `localhost`로 접속하세요. API의 허용 Origin도 `http://localhost:3020`입니다.

| 이메일               | 닉네임·캐릭터       | 역할   | 초기 해바라기씨 |
| -------------------- | ------------------- | ------ | --------------- |
| `leader@hamfit.test` | 테스트크림·크림     | 그룹장 | 300개           |
| `member@hamfit.test` | 테스트그레이·그레이 | 그룹원 | 300개           |

비밀번호는 두 계정이 같으며, 로컬 비공개 파일 `backend/.local/frontend-manual/accounts.json`에 보관합니다. `.local`은 Git에서 제외합니다. 두 계정을 동시에 확인하려면 **일반 창과 시크릿 창**, 또는 서로 다른 브라우저를 사용하세요. 같은 브라우저 프로필의 탭들은 로그인 상태를 공유합니다.

두 계정 모두 기본 캐릭터 2종·basic 자세만 보유합니다. 테스트용 측정 입력과 운동 설정을 저장했고 실제 데이터 담당 알고리즘으로 오늘 루틴을 생성했습니다. 다음날에는 화면에서 오늘 운동을 새로 준비하면 됩니다.

## 추천 확인 순서

### 1. 상점 → 옷장 → 재로그인

1. 그룹장 계정으로 로그인하고 하단 **상점**을 엽니다.
2. 모자에서 **헬멧**을 선택하고 구매를 확정합니다. 잔액은 `300 → 270`이 됩니다.
3. **노란 야구점퍼 25개**, **하얀 테니스 치마 20개**, **궁금 자세 50개**도 구매하면 잔액은 `175개`입니다. 구매만으로 대표 코디가 바뀌지 않는지 확인합니다.
4. 오른쪽 위 **내 옷장**에서 구매한 항목을 선택하고 **코디 저장**을 누릅니다. 크림·그레이 모두 변경 가능합니다.
5. 메인·내 프로필에 저장한 코디가 보이는지 확인합니다. 새로고침·로그아웃·재로그인 후에도 유지되어야 합니다.
6. 그룹원 계정으로 같은 그룹을 열면 그룹장의 저장된 대표 코디가 보여야 합니다.

테스트 DB에만 FE 이미지에 대응하는 의상 3종과 지원 조합을 등록했습니다. 자세는 **궁금 50개·러닝 70개**를 테스트 구매 가능 상태로 두었습니다. 이 설정은 운영 상품 등록이나 자세 가격 확정을 뜻하지 않습니다. 다른 자세의 `가격 확정 전` 구매 제한은 유지합니다. 기존 합쳐진 스포츠웨어 4종의 분리 완료를 의미하지도 않습니다.

### 2. 2인 그룹 미션 시작

1. 그룹장으로 [테스트 미션 시작](http://localhost:3020/groups/ad97e080-b409-49de-952f-372fc5299179)을 엽니다.
2. **새 미션 시작 → 미션 시작**을 누릅니다.
3. 씨앗 그림과 `물 0 / 28번 · 시작 인원 2명`이 표시되어야 합니다.
4. 그룹원 화면에서도 같은 진행 상태가 보여야 합니다. 그룹원에게는 시작 버튼이 없어야 합니다.
5. 아래 운동 루틴을 전체 완료한 후 그룹 화면을 다시 열면 본인의 기여와 전체 물 횟수가 1 증가합니다. 같은 날 다시 시청해도 중복 증가하지 않아야 합니다.

그룹 미션은 **루틴 전체 완료 전에 시작**하세요. 이미 완료한 운동을 소급해서 물 주기로 계산하지 않습니다. 미션 시작 후 들어온 계정은 이번 미션에 참여하지 않습니다.

### 3. 운동 순서·선택 세트·완료 화면

1. 메인 또는 운동에서 **첫 운동부터 시작**을 누릅니다.
2. **운동 시작** 후 영상을 시청합니다. 실제 시청 구간이 80% 이상일 때 **운동 완료 → 완료 확인**으로 기록합니다. 재생 위치만 끝으로 옮기면 완료되지 않습니다.
3. 완료 화면의 **처방대로 따라 하기 (선택)**를 엽니다. 반복형은 횟수 버튼, 유지형·시간형은 타이머를 사용합니다. 세트와 휴식은 서버에서 받은 처방대로 표시되어야 합니다. 타이머 일시정지와 다음 세트 이동도 확인합니다.
4. 선택 세트를 생략하고 **다음 운동으로** 이동할 수 있어야 합니다. 세트 수행 여부는 영상 80% 완료 기록을 바꾸지 않습니다.
5. 마지막 운동까지 마치면 **오늘 운동 마치기 → 오늘의 운동 완료 → 다음 → 현재 N일 연속 → 메인으로** 진행합니다.

2026-10-01 그레이 계정에는 **고양이 자세(반복형) → 엎드려 버티기(유지형) → 점프하며 뛰기(시간형)**가 배정됐습니다. 총 영상 길이는 약 3분 10초입니다. 다음날 추천은 달라질 수 있습니다. 유산소 안내는 별도 권장 사항이며 루틴 완료 조건에 포함되지 않습니다. 운동 기록은 한국 시간 자정까지 저장해야 합니다.

### 4. 그룹 룰렛

1. [테스트 룰렛 준비](http://localhost:3020/groups/59516c16-42b7-406f-8a23-968e632eed6d)를 엽니다.
2. 완성된 해바라기와 `물 28 / 28번`을 확인합니다. 이 그룹은 각 계정에 **이용권 2장**을 준비해 두었습니다.
3. 그룹 룰렛으로 이동해 **룰렛 돌리기**를 누릅니다.
4. 이용권 1장이 사용되고, 서버가 추첨한 보상만 실제 잔액에 더해져야 합니다. 새로고침 후에도 보상 내역이 유지되어야 합니다.

완료 미션·기여 원장·이용권은 14일을 기다리지 않고 확인하기 위한 **가상 테스트 데이터**입니다. 룰렛 추첨과 잔액 지급은 기존 BE 서비스가 처리합니다. 준비된 이용권을 다 쓰면 더 돌릴 수 없는 상태가 정상입니다.

### 5. 신규 가입 → 닉네임·햄스터 → 온보딩

준비된 두 계정은 이미 프로필 설정이 끝났습니다. 이 흐름은 로그아웃한 뒤 회원가입에서 새로운 `@example.test` 이메일과 15자 이상 비밀번호, 생년월일을 입력해 확인하세요.

가입 후 **나만의 프로필**에서 닉네임과 크림·그레이를 선택하고 다음으로 이동하면 온보딩이 열려야 합니다. 새로 만든 계정의 초기 해바라기씨는 **0개**가 정상입니다. 테스트용 300개는 준비한 계정에만 지급했습니다.

### 6. 홈·프로필 피드백 확인

1. 메인 오른쪽 위에서 **알림 → 해바라기씨 잔액** 순서를 확인합니다. 잔액을 누르면 상점으로 이동합니다. 구매 후 돌아오면 차감된 잔액이 표시됩니다.
2. 미확인 알림이 있으면 알림에 **빨간 점**이 표시됩니다. 알림을 모두 읽음으로 표시한 뒤 메인으로 돌아오면 점이 사라집니다. 새 알림은 메인 진입·다른 화면에서 포커스 복귀·60초 주기로 갱신합니다.
3. **내 프로필 → 캐릭터 보유 컬렉션**은 기본 크림·그레이·basic 3개와 구매한 상품을 합산합니다. 기본 계정에서 하나를 구매하면 3→4개가 됩니다. EXP·현재 레벨과 내 운동 이력 메뉴는 표시하지 않습니다.
4. `/workouts`·`/account/workouts` 목록 페이지는 삭제됐습니다. 하단 **운동**의 달력에서 완료 날짜를 눌러 날짜별 상세·다시보기를 확인합니다. 기존 날짜 상세·다시보기 북마크는 유지합니다.
5. 그룹이 없는 계정의 메인에는 안내 문구만 있고 **그룹 만들기·가입하기** 링크는 없습니다. 하단 **내 그룹**에서 생성·가입합니다.

## 아직 실제 서버로 확인할 수 없는 화면

- 하루 루틴 완료 시 **해바라기씨 1개 지급** 및 지급 결과 화면.
- 완료 직후 **물 1번 지급 결과 화면**. 그룹 미션의 실제 물 누적은 확인할 수 있지만, 결과 화면에 필요한 영수증 응답은 아직 없습니다.
- 스트릭 5일 배수의 **개인 룰렛 이용권·추첨·보상**.

위 항목은 [BE 요청 규격](BACKEND-REQUESTS.md)의 서버 구현이 필요합니다. 테스트 서버에서도 `NEXT_PUBLIC_DAILY_REWARDS_ENABLED=false`, `NEXT_PUBLIC_PERSONAL_ROULETTE_ENABLED=false`를 유지합니다. 따라서 현재 정상 완료 동선은 스트릭 뒤 메인으로 이동합니다. 개인 룰렛은 준비 안내를 표시합니다. API 대역을 사용하는 브라우저 테스트 통과와 실제 서버 지급 완료를 구분해야 합니다.

그룹원 행의 `오늘 확인 불가`는 현재 그룹 API가 `todayWorkoutCompleted`를 반환하지 않아 표시됩니다. 실제 루틴 전체 완료·스트릭·미션 물 누적 여부는 각각 운동 화면과 미션 상단에서 확인하세요.

## 서버 재실행

지금은 서버를 실행해 두었습니다. 이 컴퓨터에서 종료된 경우 저장소 루트에서 다음 명령을 실행하세요.

```bash
bash backend/.local/frontend-manual/start.sh
```

새로 서버를 실행했다면 터미널을 열어 두세요. `Ctrl+C`는 해당 명령으로 시작한 API·FE를 종료합니다. 이미 실행 중이면 접속 주소만 출력합니다. DB와 계정은 재시작해도 유지됩니다. 이 명령은 테스트 데이터를 초기화하지 않습니다.

프론트 소스를 수정한 뒤에는 테스트 서버를 종료하고 다음 순서로 다시 빌드·실행하세요.

```bash
bash backend/.local/frontend-manual/build-frontend.sh
bash backend/.local/frontend-manual/start.sh
```

이 환경의 API 스냅샷·빌드·Python·DB·실행 스크립트는 `backend/.local/frontend-manual/`에 있습니다. 현재 컴퓨터에 준비한 환경이므로 새 체크아웃에 자동 설치되는 기능은 아닙니다. 기존 `frontend/.env.local`이나 원래 `backend/.env`를 수정할 필요가 없습니다.

## 준비 과정에서 확인한 결과

- 실제 API와 브라우저: 두 계정 로그인, 구매 4건과 잔액 `300 → 175`, 의상 3부위 코디 저장·새로고침, 2인 미션 시작, 그룹 룰렛 이용권 사용·실제 잔액 지급을 확인했습니다.
- 별도 검증 계정으로 실제 영상 3개를 탐색 없이 2배속 재생하고, FE 완료 요청 → 다음 운동 → 전체 완료 → 스트릭 1일 → 메인 → 그룹 물 `0 → 1`을 확인했습니다.
- 최종 테스트 빌드에서 실제 회원가입 → 닉네임·그레이 저장 → 온보딩, 신규 계정 잔액 0개를 확인했습니다.
- 실제 연동 중 발견한 코디 저장 요청의 불필요한 조회 필드를 제거했습니다. API 대역도 추가 필드를 거절하도록 보강했습니다.

- 검증 전용 계정 3개와 그 그룹들은 삭제했습니다. 위 사용자용 계정 2개의 잔액 300개·미구매·룰렛 이용권 2장은 그대로 남겼습니다.
