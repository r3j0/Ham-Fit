# 하루 운동 프론트 연동

기준: 백엔드 [PR #9](https://github.com/r3j0/project-health/pull/9), `8d09df968fdcdac9ba6a10639bce19b1fad27bbc` (2026-09-27). 기존 인증·측정 구조와 API v1을 유지하고 새 운동 경로만 추가한다. 추가 런타임 의존성은 없다.

## 화면과 계약

- 가입: 날짜 전용 `dateOfBirth` 필수 입력. 로그인 본문과 인증 응답의 기존 user 타입은 유지한다.
- `/account`: `GET/PATCH /users/me/profile`로 기존 사용자의 생년월일을 보완한다. PATCH에 CSRF 헤더를 보낸다. 현재 만 나이는 서버 값이며 기존 측정 나이에서 생년월일을 추정하지 않는다. 프로필 조회·저장 실패 중에도 로그아웃과 기록 이동은 가능하다.
- `/`: 조회만으로 추천하지 않는다. `GET /workouts/current`의 null은 정상 빈 상태다. 추천 버튼에서 빈 본문과 UUID 요청 키로 `POST /workouts/today`를 호출한다. 오류 코드에 따라 생년월일·측정 입력·지원 연령을 안내한다.
- `/workouts/:id`: 실제 배정과 검증된 `playbackUrl`로 플레이어를 표시한다. unavailable, duration_mismatch, 실제 미디어 로드 오류를 구분해 재시도를 제공한다. 원본 HTTP URL로 우회하지 않는다.
- `/workouts`: 배정일과 최근 수행일을 구분해 표시한다. 미시작·미진행·중단·완료를 유지하며 커서 페이지 실패 시 기존 목록과 커서를 보존한다. 과거 미완료 배정도 상세에서 이어간다.

같은 날짜에는 완료 후에도 같은 배정만 표시한다. `koreanDate`와 `serverKoreanDate`를 비교하며 메인은 화면 복귀·60초 간격·사용자 새로고침 때 서버 날짜를 다시 읽는다. 전날 배정을 오늘 배정으로 간주하지 않는다. 자정을 넘은 미확정 생성 요청은 원래 키로 원래 배정을 확인한 후 새 요청 키로 오늘 배정을 요청한다.

## 플레이어와 저장

`lib/playback-session.ts`가 직렬 전송과 상태 복구를 담당하고 `components/workout-player.tsx`가 브라우저 미디어 이벤트를 연결한다. 추천 계산·진행률·50% 판정은 서버 응답을 사용한다.

- 시작 또는 재개를 서버가 확인한 뒤 재생 컨트롤을 활성화한다.
- 시청 구간은 네이티브 `HTMLMediaElement.played`에서 읽는다. 탐색 위치 또는 재생 시간의 차이를 시청량으로 만들지 않는다. 약 5초마다, 탐색·일시정지·종료·완료 때 구간을 전송한다. 구간은 요청당 1,000개 이하로 나눈다. 반복·겹침 구간은 서버가 합집합으로 집계한다.
- `pause`와 자연스러운 영상 끝은 진행 중을 유지한다. `end`는 서버가 50% 미만이면 미진행, 이상이면 중단으로 판정한다. `complete`는 별도 사용자 확인이 있어야 보낸다. 완료에 시청 비율 조건을 추가하지 않는다.
- 서버가 거절한 요청은 최신 상태 확인과 명시적 폐기를 제공한다. 응답을 받지 못한 요청은 폐기하지 않고 같은 키·본문으로 다시 확인한다. 다른 기기에서 완료했다면 서버 완료 상태를 보존하고 후속 진행 쓰기를 중단한다.
- 계정·배정별 요청 큐를 해당 탭의 `sessionStorage`에 전송 전에 저장한다. 재전송은 원래 deviceId·sequence·키·본문을 유지한다. 새 플레이어는 새 UUID 스트림을 사용해 탭 복제나 재진입 시 순서 번호가 충돌하지 않게 한다. 미확정 저장 복구 전에는 재생을 막는다.
- 작성 권한을 잃은 이전 화면의 응답은 새 큐를 지우거나 현재 화면을 갱신하지 않는다. 인증 만료는 큐를 보존하고 명시적 로그아웃·계정 변경은 폐기한다. 토큰과 비밀번호는 저장하지 않는다.
- 화면 이탈·숨김에서 재생을 멈추고 pause를 가능한 경우 동기적으로 큐에 기록한다. 다음 진입에서 남은 큐를 재확인한다. 문서 강제 종료 전 마지막 몇 초, 탭 종료·저장소 삭제 이후 복구는 보장하지 않는다. 저장소가 차단되면 같은 문서의 메모리로 유지한다.

`progress.durationSeconds`는 카탈로그 기준이다. 검증된 실측 길이가 더 길 때만 해당 실측 끝점까지 보내며 서버가 정규화한다. 실제 체력 개선으로 해석할 수 없는 weightAdjustment는 점수·보상으로 표시하지 않는다.

## 검증과 실행

```sh
npm run check
npm run format:check
npm run test:e2e
```

2026-09-27 최종 검증: 단위 검사 **44개**, 전체 Chromium 브라우저 검사 **38개** 통과. 린트·타입 검사·프로덕션 빌드·서식 검사와 `git diff --check`도 통과했다. 실제 인증 제한을 유지했으며, 전체 연속 실행에서 발생하는 429는 서버의 대기 시간을 지킨 뒤 재시도했다.

브라우저 테스트는 PR #9 백엔드, 격리된 로컬 PostgreSQL과 수입된 카탈로그를 전제로 한다. 운영 DB를 사용하지 않는다. 테스트 사용자·측정·배정은 전용 로컬 DB에만 생성한다. 기존 인증·측정 회귀에 가입 생년월일 입력과 새 메인 화면 기대값을 반영했다.

단위 검사는 nullable 응답과 오류 코드, 날짜 검증, 큐의 계정 격리·이전 응답 차단·저장소 실패·순서·정확한 재전송·구간 제한을 검증한다. 운동 E2E는 실제 인증·측정·배정·이벤트 API를 사용한다. 재생 구간·영상 끝을 결정적으로 검사하기 위해 생성한 MP4와 Range 응답만 대체한다. 페이지 재시도 테스트의 추가 이력 행·커서와 오류 응답도 테스트 fixture이며 운영 경로에는 포함되지 않는다.

추가로 실제 국민체력100 `0AUDLJ08S_00276.mp4` (68초)의 브라우저 재생과 시청 구간 저장을 확인했다. 이는 모든 영상의 전체 재생 검증을 의미하지 않는다. 공식 미디어 검사에서는 729개 검증 통과, 2개 원본 오류를 재확인했다. 실제 모바일 기기와 Safari의 재생·백그라운드 동작은 별도 확인이 필요하다.

서버를 배포할 때 마이그레이션·카탈로그 수입과 별도 미디어 검증 파일 제공이 필요하다. 이번 프론트 작업은 백엔드 코드·운영 DB·배포를 변경하지 않는다.
