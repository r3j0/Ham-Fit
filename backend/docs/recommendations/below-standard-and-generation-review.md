# 기준 미달과 추천 생성 시점 검토 — 2026-09-29

사용자 요청: 국민체력100 실제 기준에서 below_standard가 필요한지 확인하고, 운동 완료 후 요청 또는 KST 날짜 전환 시 생성하는 흐름을 data-analysis 기준으로 검토한다. 이번 작업은 검토이며 등급 변환·루틴 생성 API 동작은 변경하지 않았다.

## below_standard는 필요한 내부 상태다

현재 BE는 개별 종목의 공식 기준 충족 여부를 평가한다. `below_standard`는 공식 인증등급 이름이 아니라 **유효한 측정값이 있지만 등록한 최저 종목 기준을 충족하지 않는 상태**를 표현하는 내부 코드다. 미측정·정보 부족·기준 미확보와 구분해야 한다.

2026-09-29 다시 확인한 [공식 인증기준 표](https://nfa.kspo.or.kr/reserve/0/selectMeasureGradeItemListByAgeSe.kspo)에서 성인 남성 만 25–29세 교차윗몸일으키기는 1/2/3등급 기준이 각각 51/45/38회다. 37회나 0회는 유효한 측정일 수 있으나 이 표의 어느 종목 등급 기준도 충족하지 않는다. 이 경우를 미측정이라고 반환하면 실제 측정 사실이 사라지고 다음 목표 38회를 설명할 수 없다.

또한 성인 민첩성·순발력은 공개 인증표에서 1·2등급 수치를 제공하고, 3등급 표에는 해당 항목이 없다. 남성 만 25–29세 10m 왕복달리기 2등급 기준은 11.2초이므로 11.3초는 현재 등록한 최저 기준 밖이다. **below_standard가 언제나 '3등급 미달'을 뜻하는 것도 아니다.** 없는 3등급 경계나 4등급을 추정하면 안 된다. 이것만으로 종합 인증 탈락이나 전체 체력 수준을 판정하지 않는다.

[공식 인증단계](https://nfa.kspo.or.kr/intro/step.kspo)의 종합 4·5·6등급은 여러 항목을 조합하는 조건이다. 성인 4등급은 심폐지구력과 근력의 3등급 기준 충족, 5등급은 둘 중 하나의 기준 충족 등으로 구분된다. 따라서 교차윗몸일으키기 하나의 기준 미달을 종합 4등급으로 치환할 근거가 없다. 공식 사이트는 문화체육관광부 고시 제2025-0027호를 안내하고 있다. 종합 인증서와 앱의 항목별 참고 평가는 계속 구분한다.

### data-analysis와의 경계

`recommendation_v2.py`는 숫자 1/2/3 이상과 null을 처리하며 별도 상태 입력은 받지 않는다. BE의 status를 유지해야 한다는 판단과, 추천 필요도를 얼마로 정할지는 별개다. 공식 인증표는 추천 need를 정해 주지 않는다.

- 측정 저장/응답: below_standard 및 grade=null 유지가 타당하다.
- 현재 추천 입력: null 전송은 원본이 수용하지만 미측정과 의미가 합쳐진다.
- 후속 계약: 데이터 팀이 기준 미달을 별도 상태로 받거나 추천용 그룹으로 명시적으로 매핑해야 한다. BE만 임의의 4/5/6등급을 만들거나 Python 계산식을 복제하지 않는다.
- 청소년 기준을 확보하지 못한 BE 항목은 criteria_unavailable로 유지한다. 성인 결론으로 청소년 등급을 생성하지 않는다.

## 루틴 생성은 원본의 두 함수가 가진 날짜 의미에 맞춰야 한다

원본 `recommendation_v2.py`에는 두 층이 있다.

1. `run_recommendation(..., current_date=D)`: D까지의 로그를 받아 D+1 루틴과 D→D+1 노출도 변화를 반환하는 서비스 진입 함수.
2. `recommend_workout_routine(..., current_date=T)`: T일의 루틴 자체를 반환하는 원본 함수. 바로 위 진입 함수가 내부적으로 이 함수를 T=D+1로 호출한다.

현재 BE는 1번만 호출한다. 따라서 9월 30일 00:00에 실제 오늘을 current_date로 전달하면 10월 1일 루틴이 나온다. 이를 9월 30일 배정으로 이름만 바꾸면 최근 로그의 경과일·감쇠 기준이 틀어진다.

### 사용자 제안에 대한 검토안

| 상황                                                                 | 대상 날짜                | 원본 계산 연결                                                                       |
| -------------------------------------------------------------------- | ------------------------ | ------------------------------------------------------------------------------------ |
| D일 오늘 루틴 전체 완료 후 사용자가 요청                             | D+1                      | 기존 run_recommendation(current_date=D) 사용. 완료 저장 커밋 후 읽은 로그 전달       |
| D일 운동이 끝나지 않은 채 D+1일 00:00 KST로 전환했고 D+1 배정이 없음 | D+1, 즉 실행 시점의 오늘 | 원본 recommend_workout_routine(current_date=D+1)을 이용하는 당일 보완 생성 경로 필요 |
| D+1 루틴이 이미 있음                                                 | 기존 D+1                 | 저장값 반환. 다시 생성하거나 수행 진행을 초기화하지 않음                             |

두 번째 경로는 원본 계산을 그대로 호출할 수 있지만 현재 서비스 진입 함수/BE transport에는 없는 연결이다. 데이터를 바꾸지 않고도 기술적으로 가능하며, 함수 이름·반환 포장과 weightAdjustment의 기준을 명시한 연동 계약이 필요하다. 과거 날짜를 실제 오늘이라고 숨겨 보내거나 BE에서 추천식을 다시 구현하지 않는다.

당일 보완 생성 시 weightAdjustment가 필요하면 원본 calculate_weight_adjustment(logs, D)를 사용해 D→D+1 변화로 명시한다. 입력은 D+1 자정 **미만**에 확정된 수행 로그로 한정한다. 그 값은 당일 실시간 운동 효과가 아닌 전날 마감 스냅샷이다. 저장 필드 referenceDate=D, assignmentDate=D+1, createdAt=실제 실행 시각을 구분해야 한다.

원본에서 완료는 completed=true, 중단 로그는 false이며 중단은 노출도 0.5배로 계산된다. 운동을 전혀 하지 않은 항목까지 자정에 false 로그로 만들면 안 된다. 현재 BE에서 false로 전달하는 것은 interrupted 대표 결과뿐이다. 자정을 넘긴 in_progress는 completed로 바꾸지 않으며, 어느 날짜의 수행으로 마감할지는 별도 명시가 필요하다.

데이터 모듈에는 스케줄러·DB 배정·사용자 요청 조건이 없다. KST 자정 트리거, 오늘 전체 완료 확인, 첫 이용자에게 오늘 루틴 제공, 실패 재시도 및 날짜별 중복 방지는 BE 책임이다. '하루 한 번'은 **배정 대상 날짜당 한 번**으로 보장해야 한다. 자정에 오늘 루틴을 생성하고 저녁에 내일 루틴을 생성하는 두 호출은 서로 다른 날짜 배정이다.

### 완료 조건과 예외

- '오늘의 운동 끝남'은 이번 검토에서 전체 항목 completed로 해석했다. end(중단)나 항목 하나 완료와 구분한다. 현행 data 원본이 이 서비스 조건까지 정의하는 것은 아니다.
- 늦은 밤 완료와 자정 작업이 겹쳐도 같은 대상 날짜의 배정은 한 건이어야 한다.
- 오늘 할당이 없는 첫 이용자에게는 완료 선행 조건을 요구할 수 없다. 당일 보완 생성과 같은 원본 날짜 기준으로 별도 진입이 필요하다.
- 자정 후 과거 운동을 이어서 완료한 기록을 과거 날짜로 임의 이동하지 않는다. 이미 확정된 배정 재계산 여부는 기존 하루 한 번 저장 규칙과 함께 결정해야 한다.
- 자정 작업이 지연되면 덮어쓴 현재 대표 결과만으로 자정 당시 상태를 복원하지 못할 수 있다. 정확한 마감 스냅샷이 필요하면 저장된 이벤트의 서버 수신 시각으로 당시 결과를 복원하는 처리가 필요하다.
- 이 문서는 설계 검토안이며 신규 자정 작업·API/DB 정책은 아직 구현하지 않았다.

## 검토 검증

원본 파일을 수정하지 않고 나이 13/25/64 × 목적 3종 × 운동량 3종 = 27개 조합을 실행했다. 같은 KST 자정 직전 중단 로그와 난수 시드에서 `run_recommendation(current_date=2026-09-29).nextWorkout`과 `recommend_workout_routine(current_date=2026-09-30)`의 전체 반환값이 일치했다. 전날 기준 원본 calculate_weight_adjustment 결과도 wrapper 반환값과 일치했다. 이는 날짜 의미 및 원본 함수 재사용 가능성 검사이며, 제안한 자정 DB 처리의 구현/통합 검증은 아니다.

기존 종목 평가·미디어 단위 검사 61개와 새 검사 스크립트의 파서/HTTP/MP4 검사 11개가 통과했다. 현재 환경 설정을 로드한 새 Node 프로세스에서 mediaFor로 272개 모두 verified임을 확인했다.
