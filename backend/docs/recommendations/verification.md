# 추천 알고리즘 연결 제거 검증 — 2026-09-28

사용자 정정에 따라 API 설계, DB 스키마·기존 마이그레이션, 생년월일·닉네임, 측정, 배정/진행 상태는 유지한다. 데이터 소스 사본·TypeScript 계산 엔진·입력 변환과 데이터 전용 스크립트/대조 검사만 제거한다. [현재 연결 경계](provenance.md)를 따른다.

운영 모듈은 실제 계산기 대신 503 `RECOMMENDATION_NOT_CONNECTED`를 반환하는 미연결 구현을 등록한다. 합성 데이터/계산 대역은 테스트 파일에서만 주입한다. 이 검사는 API·DB 계약 검증이며 데이터 팀 알고리즘 검증이 아니다.

## 실제 실행 결과

- `npm run check`: exit 0. Prisma 스키마 검증/클라이언트 생성, 포맷, lint, 타입 검사, 단위 테스트, PostgreSQL E2E, Nest 빌드 통과.
- 단위 테스트: 17개 파일, 270개 통과.
- PostgreSQL E2E: 16개 파일, 322개 통과. 전용 `project_health_test`의 임시 스키마에서 기존 14개 마이그레이션 적용 및 재적용 후 스키마를 정리했다.
- 실제 앱 모듈이 미연결 계산기를 사용하여 503을 반환하고, 임의 배정을 만들지 않는지 확인했다. 기존 배정 조회의 계산 실패 및 이벤트 저장 롤백도 검증했다.
- 알고리즘을 대체한 테스트 대역으로 기존 일자별 배정·중복 요청·소유권·진행 구간·50% 경계·중단 후 완료·미디어 입력 계약을 검사했다. 실제 추천 정확도 대조는 포함하지 않는다.
- `git diff --check`와 변경 문서의 내부 링크 확인 통과.
- API 컨트롤러, Prisma 스키마/마이그레이션, 계정·측정·프로필·기존 커리큘럼 코드와 프런트엔드는 HEAD 대비 변경 없음.

샌드박스 내 첫 전체 검사는 로컬 HTTP listen 권한(EPERM)으로 중단됐고, 허용된 실행 환경에서 재실행해 통과했다. PostgreSQL 드라이버의 기존 동시 query deprecation 경고는 실패를 일으키지 않았다. 운영 DB 적용·배포·Git push는 수행하지 않았다.
