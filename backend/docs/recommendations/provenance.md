# 추천 알고리즘 연결 상태

2026-09-29 추가 결정: [여러 운동 루틴 API](routines-api.md)는 원본 `data-analysis/src/recommendation_v2.py`를 Python 프로세스로 직접 호출한다. 루틴·항목별 저장과 진행을 추가했으며 원본·데이터는 복사하거나 수정하지 않는다. **아래 미연결 설명은 기존 `/api/v1/workouts` 단일 영상 경계에 적용**된다. 신규 `/api/v2/workout-routines`는 별도 `RoutineAlgorithm`과 실제 Python 연결을 사용한다. 당일용 `recommend_workout_routine`을 호출하며 하루 한 루틴만 저장한다. v1 루틴 API는 종료 안내(410)를 반환한다.

2026-09-28 사용자 결정: **API 설계와 DB 구조는 유지하고 데이터 팀 알고리즘을 BE에 연결한 구현만 제거한다.** 데이터 팀원이 수정한 코드를 데이터 브랜치에 push한 뒤 main으로 병합하고, BE 브랜치를 main에 rebase할 예정이다.

## 현재 유지하는 부분

- `/api/v1/workouts`의 경로·인증·요청 형식과 성공 응답 설계.
- 생년월일·닉네임, 측정 기록과 저장된 평가, 기존 온보딩.
- 일자별 배정·요청 키·동시성·진행 구간·중단/완료·이력 및 카탈로그 저장 구조.
- 기존 마이그레이션. 이번 변경은 DB 데이터를 삭제하거나 마이그레이션을 적용하지 않는다.

## 제거한 연결 구현

- `backend/data/recommendation/`에 복사했던 Python, 노트북, CSV/JSON과 변환 카탈로그·고정 해시.
- TypeScript로 옮겼던 추천 엔진과 등급/need 변환 어댑터.
- 원본 데이터 변환·수입·MP4 탐색 스크립트, Python 대조 및 추천 시뮬레이션.
- 특정 데이터 커밋·영상 731개에 의존하던 운영 코드와 검사.

데이터 브랜치 자체와 해당 브랜치의 원본 파일은 변경하지 않는다. 과거 파일은 Git 이력에서 확인할 수 있지만 현재 앱의 실행 경로에는 없다.

## BE에 남긴 연결 경계

`src/recommendations/workout-algorithm.ts`의 `WorkoutAlgorithm`은 구현 없는 인터페이스다. 최신 측정의 저장된 원본 평가·현재 나이·카탈로그·대표 수행 기록·기준 시각을 입력으로 받고, 추천 영상/버전/계산 스냅샷 또는 응답용 `WeightAdjustment`를 반환하는 경계만 정의한다. 점수식, 반감기, need 계산, 동점 선택, 반올림 규칙은 포함하지 않는다.

실제 모듈에는 `DisconnectedWorkoutAlgorithm`만 등록되어 있다. 추천 생성 또는 노출도 계산이 필요하면 HTTP 503 `RECOMMENDATION_NOT_CONNECTED`를 반환하며 결과를 임의로 만들지 않는다. 현재 배정이 없는 GET은 기존처럼 null/빈 이력을 반환한다. 저장된 배정도 응답에 노출도 계산이 필요하므로 계산기 미연결 상태에서는 503이 될 수 있다. 결과 응답 계산 실패 시 이벤트 저장 트랜잭션도 롤백된다.

`workout-contracts.ts`는 기존 API/저장 형식만 보존한다. `catalog.ts`는 외부에서 명시적으로 전달된 카탈로그의 필수 필드·숫자 범위·고유 ID·내용 해시를 검사한다. 데이터 파일을 읽거나 특정 커밋/개수/가중치 합으로 제한하지 않는다. `WorkoutCatalogService`는 검증된 입력의 저장·활성화만 담당하며 자동 수입하지 않는다.

## main 병합·BE rebase 이후

데이터 팀의 새 코드를 확인한 후 별도 연결 작업으로 구현체를 등록한다. 현재 변경에서 새 알고리즘을 예상하여 구현하거나 TypeScript로 다시 옮기지 않는다. 재연결 시 데이터 팀의 실제 입출력·계산 기준과 BE 계약 차이를 확인하고 어댑터 및 실제 알고리즘 대조 검사를 작성한다.

현재 BE E2E는 테스트 폴더의 합성 카탈로그와 명시적인 테스트 대역으로 API·DB 계약만 검사한다. 이 대역은 운영 모듈에서 사용하지 않으며 실제 추천 정확도 검증을 의미하지 않는다.
