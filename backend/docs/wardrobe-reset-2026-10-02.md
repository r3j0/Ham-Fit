# 기존 의상 초기화

2026-10-02 사용자 요청으로 프론트엔드 카탈로그의 기존 의상 54개(모자·상의·하의 각각 18개)를 초기화했다. 삭제 대상은 해당 카탈로그의 상품 ID로 제한했다.

운영 Supabase `ham-fit-db` 조회에서 실제 등록된 대상 상품은 `clothing.mint-shirt` 1개였다. 사용자 선택에 따라 **환급 없이** 상품 1개, 구매 1건, 보유 1건, 연결된 구매 거래 1건 및 착용 조합 2개·조합 항목 2개를 삭제했다. 대상 의상의 현재 착용과 룰렛 지급 기록은 없었다. 재화 잔액은 변경하지 않았다.

삭제 전에 대상 기록을 비공개 백업으로 보관하고, 삭제 후 기본 프로젝트의 Git 제외 경로 `backend/.local/wardrobe-reset-2026-10-02/backup.json`에도 보존했다. 백업 파일 권한은 0600이다. 작업은 잠금/실행 제한을 둔 한 트랜잭션으로 처리했다. 조합의 삭제 방지 트리거 두 개만 트랜잭션 안에서 일시 중지하고 복구했으며, 완료 후 활성 상태를 확인했다. 테이블·FK·그 밖의 트리거는 변경하지 않았다.

삭제 후 운영 의상 상품·대상 구매·보유·조합 항목이 모두 0건임을 확인했다. 캐릭터 상품 2개와 자세 상품 17개는 보존했다. 운영 `avatar_render_catalogs`는 작업 전후 0건이었다. 과거 Prisma 마이그레이션과 테스트용 상품 fixture는 운영 신규 상품 등록으로 사용하지 않는다.

프론트엔드에서는 대상 이미지 1,693개와 이전 bundle을 제거하고 빈 카탈로그/배포 bundle로 교체했다. 편집기의 기존 원본 PNG 1,248개·생성 카탈로그·검수 목록도 비웠다. 기본 캐릭터·자세 파일은 유지했다. 코드 변경을 병합·배포하면 운영 프론트엔드에도 빈 카탈로그가 반영된다.

새로 등록할 때는 최신 저장소를 준비하고, 기존 로컬 초안이 있으면 **프론트엔드 편집본 불러오기**로 빈 목록을 적용한다. 이후 **상품 추가 → 의상 폴더 가져오기 → 조정/픽셀 저장 → 프론트엔드 내보내기 → 프론트엔드 배포 → 상품 ID·가격 DB 등록** 순서로 진행한다. 기존 의상 삭제 SQL을 새 등록 후 반복 실행하지 않는다.
