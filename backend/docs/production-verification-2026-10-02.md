## 발견한 회귀와 수정

### PR #31 readiness 권한 검사 누락

한 번의 SQL로 줄인 readiness의 미참조 CTE는 PostgreSQL에서 테이블·컬럼 이름을 해석하지만 실행 계획에서 제거되므로 SELECT 권한 검사까지 보장하지 않는다. 실제 제한 역할에서 `group_mission_water_choices`의 SELECT 권한을 회수해도 기존 구현은 true를 반환했다. 신규 테스트가 수정 전 실패하는 것을 확인했다.

`pg_catalog.has_column_privilege`로 필수 컬럼의 SELECT 권한을 명시적으로 확인한다. 한 번의 SQL, 사용자·이력 행 미조회, 카탈로그 존재 확인을 유지한다. 테이블 권한 누락 및 컬럼 단위 권한의 일부 누락은 false, 권한 복구 후에는 true다. 실제 운영 런타임 계정으로도 수정 SQL을 읽기 전용 실행하여 true를 확인했다. 현재 운영 권한이 빠져 있다는 뜻은 아니며, 향후 권한 누락을 탐지하지 못하는 결함을 고친 것이다.

첫 전체 브라우저 실행을 무조건 통과로 기록하지 않았다. 공유 IP 호출 한도 429는 테스트 파일 사이 로컬 전용 rate-limit 테이블을 초기화하여 격리 재검증했다. 운영 제한은 변경하지 않았다. 비활성 기능을 전제로 한 빌드에서는 개인 룰렛 테스트가 실패/skip하므로 해당 검증은 명시적으로 활성화한 별도 빌드에서 수행했다.

영상 시나리오의 초기 로컬 실패는 미디어 보고서 경로 누락과 Git CRLF 변환으로 인한 CSV 해시 차이였다. 데이터 원본을 수정하지 않고, 운영 배포 번들의 canonical 원본 CSV/Python과 검증 보고서를 읽도록 로컬 설정을 맞춘 뒤 통과했다. 운영 번들의 CSV SHA-256은 보고서의 `db329d71dfdbc04ca66fb6c63ea15667a5b50d6bdeb8d8e4df9db8cabc602380`과 일치한다.

전체 기본 포맷 검사는 이 환경의 CRLF 체크아웃 때문에 실패했다. 원본 파일을 일괄 수정하지 않고 `prettier --check . --end-of-line auto`로 모든 BE 파일의 포맷 통과를 확인했다. 변경 파일은 기본 Prettier로 정리했다.
