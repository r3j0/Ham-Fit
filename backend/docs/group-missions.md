# 그룹 미션의 구현 경계와 결정 사항

2026-09-29. 이번 구현은 확정된 그룹 관리·가입·권한·알림을 완성하는 범위다. 개인 미션 성공 → 그룹 진행도 증가 → 목표 달성 → 해바라기에 씨앗 투입 → 성장이라는 방향을 유지한다. 개인 씨앗 지갑이나 기존 `UserCurrency` 잔액을 전제로 삼지 않는다.

## 확인한 기존 코드와 이번 연결 범위

| 기존 구조                                           | 사실·연동 지점                                                                                                                                       |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CurriculaService.complete`                         | 내부 개인 커리큘럼 완료. 사용자 행 잠금 아래 `assigned → completed`, 동일 완료 재시도는 기존 결과 반환                                               |
| `RecommendationsService.event`                      | 기존 단일 영상 일별 배정의 진행 이벤트·대표 완료 상태 저장. 요청 키·device sequence·revision으로 중복 처리. 완료 분기를 후속 연동 대상으로 사용 가능 |
| `WorkoutRoutinesService.event`                      | 여러 운동 루틴의 **항목별** 완료·이벤트 저장. 항목 완료와 전체 루틴 완료는 서로 다르며 어떤 단위가 개인 미션 성공인지 결정 필요                      |
| `UserCurriculumAssignment` / `WorkoutProgressEvent` | 기존 완료 기록과 개별 전송 이벤트. 클라이언트 이벤트 여러 개를 여러 번의 개인 성공으로 세면 안 됨                                                    |
| `WorkoutRoutineItem` / `WorkoutRoutineEvent`        | 항목별 최종 완료와 전송 이벤트. 전체 루틴 결과는 항목 상태를 합성해 조회하며 별도 그룹 미션 상태는 없음                                              |
| `UserCurrency`                                      | 기존 개인 재화. 그룹 씨앗으로 사용하거나 가입/탈퇴 시 이동하지 않음                                                                                  |
| `member-profile.ts`                                 | 기존 개인 일별 완료 데이터·KST 스트릭 규칙을 재사용. 개인 활동 조회와 그룹원 조회가 공통 함수를 호출                                                 |

운영 경로에 그룹 미션 진행도·씨앗·보상 이벤트 호출을 연결하지 않았다. 개인 미션 성공의 그룹 반영 범위가 미정인 상태에서 모든 그룹에 자동 배포하거나 임의로 하나를 선택하지 않는다. 별도 미션 생성 API·완료 API·씨앗 지갑/사용 API도 없다.

## 이번에 보장하는 사항과 보류한 보장

- 그룹 ID와 멤버십·정확히 한 명의 그룹장, 승인/위임/탈퇴/삭제의 원자성, 저장형 알림의 중복 방지는 구현·검증했다.
- 기존 개인 운동 완료 처리·개인 재화·완료 이력은 변경하지 않았다. 그룹 삭제가 개인 완료 기록을 지우지 않는지 실제 기록으로 통합 검증한다.
- **그룹 미션/기여/씨앗/성장 테이블·서비스는 미구현**이다. 이번 범위에서 씨앗 보존이나 미션 보상의 멱등성을 실행·검증했다고 주장하지 않는다. 확정된 데이터 소유 원칙만 아래의 후속 구현 필수 계약으로 기록한다.

## 정책 확정 후 지켜야 할 데이터·트랜잭션 계약

1. 미션 회차, 씨앗, 성장, 기여 원장은 그룹 소유이며 `group_id → groups.id ON DELETE CASCADE`로 삭제한다. 멤버십을 원장의 소유자로 두지 않는다. 탈퇴·퇴출이 기여 원장 삭제나 합계 감소를 유발해서는 안 된다. 계정 영구 삭제 시 기여자 식별을 지우거나 nullable FK로 익명화할지는 별도 개인정보 정책에 맞춰 결정한다.
2. 개인 성공의 안정된 키는 완료된 배정/항목/루틴 ID 중 정책에서 고른 도메인 ID다. 재시도마다 새 이벤트 ID를 만들지 않는다. 소비자는 `(group_mission_round_id, personal_completion_id)` unique로 같은 개인 성공을 같은 회차에 한 번만 반영한다.
3. 완료 저장과 연동 이벤트 기록을 원본 완료 트랜잭션에 묶는다. 비동기 전달이 필요할 때만 DB outbox를 추가한다. 커밋 전에 외부 메시지를 보내거나 트랜잭션 밖에서 성공으로 처리하지 않는다.
4. 그룹/미션 회차 행을 잠그고 이벤트 중복 확인·진행도 원자 증가·목표 도달 판정·회차 보상 claim을 한 트랜잭션으로 처리한다. `(round_id, reward_kind)` unique 또는 조건부 전이로 한 회차의 씨앗 보상을 한 번만 지급한다.
5. 씨앗 투입·성장량 증가·기여 원장 기록은 같은 트랜잭션이다. 단계 보상이 생기면 `(group_id, growth_cycle_id, stage_id)` unique로 동일 단계 보상을 한 번만 실행한다. 전/후 성장값을 잠금 안에서 계산한다.
6. 수동 보관 후 사용으로 결정되면 그룹 보유 잔액에 조건부 차감(`balance >= amount`)·DB 음수 방지·사용 요청 키 unique를 적용한다. 자동 투입으로 결정되면 불필요한 개인/그룹 지갑을 만들지 않는다.
7. 탈퇴·퇴출·그룹 삭제와 소비의 경쟁도 그룹 행 잠금에 참여시킨다. 삭제된 그룹 이벤트는 그룹을 되살리거나 조회 가능하게 만들지 않는다.
8. 실제 PostgreSQL 동시 완료/중복 이벤트/회차 보상 재시도/성장 단계 재시도/고장 주입 통합 테스트를 추가한다. 현재 그룹 관리 테스트만으로 이 보장을 대체하지 않는다.

## 회의에서 결정할 사항

| 결정           | 필요한 내용                                                                                                |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| 반영 대상      | 성공을 당시 소속한 모든 그룹에 반영할지, 선택 그룹에 반영할지; 완료·신청·가입·탈퇴 경계에서 소속 판단 시점 |
| 개인 성공 단위 | 기존 배정 1개, 루틴 항목 1개, 전체 루틴 중 어떤 완료를 인정할지; 과거 성공 재처리 범위                     |
| 미션 회차      | 종류, 목표치, 주기, 시간대, 초기화 기준, 회차 생성 주체, 진행 중 가입/탈퇴 시 목표 처리                    |
| 씨앗 지급      | 회차별 씨앗 수, 보상 확정 시점, 성공 중복의 도메인 키                                                      |
| 투입 방식      | 자동 투입 여부, 보관 후 수동 사용 여부, 수동일 때 그룹장/구성원 권한                                       |
| 성장           | 단계, 성장량 단위/계산식, 완료 조건, 완성 보상, 다음 회차·초기화/누적 처리                                 |
| 기여 표시      | 기여자 계정 삭제 시 익명화, 남아 있는 원장의 공개 필드                                                     |

2026-09-30 프로필 연동 완료: 그룹 응답의 `profileCharacter`는 본인과 같은 저장 대표 코디다. [캐릭터·상점 계약](avatar-shop-api.md)을 따른다. 개인 해바라기씨를 미정인 그룹 씨앗/성장 보상과 연결하지 않는다.
