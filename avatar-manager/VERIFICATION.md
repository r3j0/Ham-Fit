# 검증 기록 — 2026-10-01

`feat/root/avatar-manager`의 별도 워크트리에서 검증했다. 기존 실행 서버와 애플리케이션 DB를 변경하지 않았다.

| 범위 | 결과 |
| --- | --- |
| avatar-manager | 타입 검사, 단위 검사 14개, Next.js 프로덕션 빌드 통과 |
| backend | Prisma 검증·생성, 타입 검사, lint, 단위 검사 353개, 프로덕션 빌드 통과 |
| backend E2E | 전용 테스트 DB의 임시 스키마에서 507개 통과; 마이그레이션 재실행·정리 확인 |
| frontend | lint, 타입 검사, 단위 검사 169개, Next.js 프로덕션 빌드 통과 |
| import | 포함된 manifest·원본으로 39개 의상 / 1,248개 프레임·PNG를 다시 구성하고 검증 |

변경한 backend 파일은 Prettier 검사를 통과했다. 전체 `backend/npm run check`는 기존 파일 197개의 포맷 문제에서 중단된다. 관련 없는 파일은 일괄 포맷하지 않았으며 나머지 검사 명령을 각각 실행했다.

실제 브라우저와 격리된 NestJS·PostgreSQL에서 다음 흐름을 확인했다.

1. 의상의 X/Y·너비·높이·회전 조정 후 로컬 저장.
2. 크기 조절 지우개, 스포이드의 실제 PNG 색 추출, 펜, 실행 취소·다시 실행, 수정 PNG 저장 및 원본 복원.
3. 39개 의상 전체를 등록해 서버 revision 1 확인. 수정한 민트 티셔츠의 배치와 이미지 URL을 서비스 SVG에서 확인.
4. 원본 픽셀 `[202,244,209,254]`가 수정 PNG의 같은 위치에서 `[0,0,0,0]`으로 실제 지워진 것을 확인.
5. 테스트 계정의 재화로 의상 구매, 옷장 선택, 대표 코디 저장.
6. 서버 등록본 불러오기 후 배치와 수정 PNG 재편집. 최종 빌드에서 배치 재저장·재등록 후 기존 구매·코디 유지 확인.

테스트 데이터와 미리보기 프로세스는 검증 후 정리했다. 실사용 DB에는 새 마이그레이션을 별도로 적용하고 이 브랜치의 backend와 frontend를 실행해야 한다. 관리자 앱만 실행하면서 기존 backend 서버에 연결하면 새 등록 API가 없으므로 404를 표시한다.

PR 준비 과정에서 최신 `feat/frontend/avatar-shop`을 반영하고 상점 레이아웃을 보존했다. Prisma 모델 위치와 신규 마이그레이션 이름(`20261001000500_avatar_render_catalog`)을 정리했으며, PR 대상과 최신 `origin/main` 모두 가상 병합에 충돌이 없음을 확인했다. 이후 위의 전체 검사와 빌드를 다시 통과했다.
